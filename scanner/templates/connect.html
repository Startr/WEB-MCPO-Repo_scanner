Connect your AI agent

AI agents are part of your team. Give them the same live view of what's unfinished that you have — four steps, no SDK.

Tool API: checking…

  1. 1. Give your agent an access key

    Agents authenticate the same way you do. Use an existing key from access_keys.csv, or add a row with a fresh key and a label like my-agent so you can tell its requests apart. The agent sends it as Authorization: Bearer <key>.

  2. 2. Point it at this server

    TodoScope announces its tools through a manifest and an OpenAPI spec — both public, no key needed for discovery. Give your agent the manifest URL:

    The OpenAPI spec lives at /api/mcpo/openapi.json — the manifest links to it, so most clients only need the URL above.

  3. 3. Prove it works

    One request, straight from a terminal:

    curl [origin]/api/mcpo/list_repositories \
  -H "Authorization: Bearer YOUR_KEY"

    A JSON list of your repositories comes back. From there, ask your agent: "What's still TODO in this project?"

  4. 4. Claude Code? Install the todo-scope skill

    The todo-scope skill teaches Claude Code the TODO.md convention this board reads — it bootstraps a missing TODO.md, restructures a messy one, and keeps cards in board-ready shape. 

    mkdir -p ~/.claude/skills/todo-scope
curl -o ~/.claude/skills/todo-scope/SKILL.md \
  https://raw.githubusercontent.com/Startr/TodoScope/master/.claude/skills/todo-scope/SKILL.md

    Then run /todo-scope in any project. Details in the README.

All endpoints

Endpoint Method Auth Purpose
/api/mcpo/manifest GET No Service discovery
/api/mcpo/openapi.json GET No OpenAPI 3.0 spec
/api/mcpo/scan_repository POST Yes Scan a repo, return TODOs
/api/mcpo/scan_repository_stream POST Yes Stream TODOs (NDJSON)
/api/mcpo/list_repositories GET Yes List registered repos
/api/mcpo/pull_repository POST Yes Pull latest for a repo
/health GET No Liveness + version + auth state
